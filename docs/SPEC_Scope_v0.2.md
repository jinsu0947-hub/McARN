# SPEC_Scope — 생성 범위와 지역 프리셋

버전 0.2 · Arnis 포크 · `SPEC_GenerationScope_v0.1.md`를 대체

---

## 0. 원칙

**범위(scope)를 기하 도형 하나로 먼저 확정하고, 모든 층위를 거기서 파생시킨다.**

이전 판(`v0.1`)은 "노선 띠"를 유일한 생성 단위로 못박고, 그 안에서 영도·508에 고유한 절단 규칙과 좌표 범위 판정을 하드코딩했다. 노선이 아예 없는 지역, 노선이 여러 개인 지역, 행정구역 단위로 통째로 뽑고 싶은 경우를 하나도 감당하지 못했다.

이 판은 "노선 띠"를 scope를 이루는 조각 중 하나로 내린다. **scope는 세 종류 조각의 합집합**이고, 노선·정류소·지형·도로·건물 어느 층위도 자기만의 범위 판정을 따로 갖지 않는다 — 전부 "scope 안인가" 하나로 묻는다.

---

## 1. Scope 정의

### 1.1 조각 종류

| 종류 | 정의 | 용도 |
|---|---|---|
| **사각형** (기본값) | lat/lon 경위도 또는 평면좌표(EPSG:5186) 사각형 | 범위 지정의 기본 형태. 프리셋 없이 CLI만으로 실행할 때 이것 하나만 쓴다 |
| **행정구역 폴리곤** | 국가공간정보포털 행정경계 SHP에서 특정 코드(들)로 골라낸 폴리곤 | 구·동 단위로 정확히 자르고 싶을 때. 사각형보다 실제 경계에 가깝다 |
| **노선 띠** | 노선 폴리라인 + 버퍼 폭(m) | 노선 주행 재현이 목적일 때. 폭은 조각마다 따로 지정한다 |

세 종류 모두 하나의 실행에서 몇 개든 섞어 쓸 수 있다. 조각이 하나도 없으면(프리셋이 없으면) 사각형 하나만 있는 것으로 취급한다 (§5.2).

### 1.2 합집합

scope = 조각들의 기하 합집합. 한 좌표가 scope 안이라는 것은 **조각 중 하나에라도 속한다**는 뜻이다. 조각끼리 겹쳐도 문제없다 — 합집합이므로 중복 판정만 낭비될 뿐 결과는 같다.

## 2. 생성 층위 (scope에서 파생)

| 층위 | 대상 | 범위 |
|---|---|---|
| **L0** | 지형·수면 | scope + `TERRAIN_BUFFER` |
| **L1** | 도로 | scope 내 전부 + `STUB_LENGTH` 스텁 |
| **L2** | 건물 (근경) | scope 내 전부 |
| **L3** | 건물 (원경) | scope 외접 사각형 안에서 `HIGHRISE_FLOORS` 이상만 |

`v0.1`에서 L0(지형 버퍼)와 L2(건물 버퍼)가 노선 중심선에서 각각 다른 폭을 갖던 것은, 이제 **scope 조각 자체의 폭**으로 흡수됐다. 노선 띠 조각을 150m 폭으로 넣으면 그 노선 주변 150m가 scope이고, L2는 그 scope 전체를 건물 근경으로 채운다. "건물만 더 좁게" 보고 싶으면 조각을 더 좁게 그리면 된다 — 층위별로 별도 버퍼 숫자를 관리할 필요가 없다.

`TERRAIN_BUFFER`만은 예외로 남는다. 지형은 scope 경계 바로 바깥이 뚝 끊기면 보기 흉하므로 (봉래산이 잘려나간 것처럼), scope 자체보다 한 겹 더 넓게 깐다. 이것이 청크 예산을 지배한다 — scope가 좁아도 `TERRAIN_BUFFER`를 넓게 잡으면 결국 큰 사각형을 채우는 것과 다르지 않다.

### L1. 도로

- scope 중심선과 만나는 도로: 전 구간 생성
- 그 도로에서 갈라져 scope 밖으로 나가는 도로: 분기점에서 `STUB_LENGTH`까지만 생성 후 절단, 지형으로 완만히 되돌림

스텁이 없으면 scope 경계의 교차로에서 옆길이 뚝 끊겨 도시로 보이지 않는다.

### L3. 원경

L2(scope 내부, 완전 사양)에 들지 않는 고층 건물을 간략 모드로 채운다. 구성은 `SPEC_BuildingType §8`을 따른다. L2 scope 안에 있는 고층 건물은 L3 규칙과 무관하게 L2 완전 사양이 우선한다.

## 3. 경계 처리

| 상황 | 처리 |
|---|---|
| L0 버퍼 경계 | 청크 단위로 절단. 지형 단면이 노출되나 대부분 무해한 지형이므로 감수한다 |
| L2(scope) 경계에 걸친 건물 | 건물 중심점 기준으로 포함 여부 판정. 잘라내지 않는다 |
| L1 스텁 끝 | 지형으로 완만히 되돌림 |
| L3 단독 고층 주변 | 지형이 L0 버퍼 밖이면 해당 건물 발치만 최소 지형 생성 (없으면 고층 건물이 허공에 뜬다) |

## 4. 노선과 정류소

### 4.1 포함 판정

**"scope 안인가" 하나로 통일한다.** 정류소 좌표가 scope 안이면 포함, 아니면 제외 — 이것이 유일한 신호다. 다만 "scope"가 무엇을 가리키는지는 **판정 주체에 따라 다르다** — 아래 4.1.2 참고. 별도의 지역 경계 판정(예: 행정구역 좌표 사각형을 노선 로직 안에 다시 정의하는 것)이나 "주 노선"이라서 전 구간을 봐주는 특별 취급은 코드 분기로 두지 않는다. 둘 다 scope 조각의 조합만으로 표현된다.

노선의 정류소 순서를 따라가다 **scope를 벗어나는 첫 정류소부터**(포함) 이후 전부 제외한다. 마지막으로 포함하는 정류소는 그 직전 정류소다.

### 4.1.1 조각의 두 역할

scope 조각은 관여하는 판정의 범위가 다른 두 역할로 나뉜다.

| 역할 | 해당 조각 | 관여하는 판정 |
|---|---|---|
| **영역 조각** | 사각형, 행정구역 폴리곤 | 노선 채택 판정 **전체**, 그리고 지형·도로·건물 생성 범위 |
| **노선 조각** | 노선 띠(route_strip) | **그 조각이 지정한 노선 자신**의 생성 범위와 채택 판정만. 다른 노선의 채택 판정에는 관여하지 않는다 |

판정 주체마다 scope가 다음처럼 갈린다.

```
노선 A의 채택 판정 scope = 영역 조각 전체 ∪ (A를 지정한 route_strip이 있다면 그 조각)
지형·도로·건물의 생성 scope = 전 조각의 합집합 (영역 조각 + 모든 route_strip)
```

지형·도로·건물 쪽은 여전히 순수한 합집합이다 — 노선 조각이 넓힌 땅에는 그 노선이 지나는 동안 보이는 건물·지형이 실제로 있어야 하기 때문이다(§7.1 508이 부산역·민주공원까지 완전 재현되는 이유). **다른 노선의 채택 판정만 예외다.**

**이유**: route_strip을 노선 채택의 전역 판정에도 쓰면, 그 노선이 지나가는 동네를 관통하는 전혀 무관한 다른 노선까지 전부 딸려온다. 2026-09-18 검증에서 실측됐다 — 영도 사각형 ∪ 508 노선 띠(150m)로 노선 채택을 돌렸더니 20개 → 51개로 늘었고, 늘어난 31개는 전부 508이 지나는 도심 환승 거점(남포동·중앙동·초량·부산역)을 스칠 뿐인, 영도와 무관한 순수 시내 노선이었다. **route_strip의 목적은 지정한 그 노선을 끝까지 살리는 것이지, 그 노선이 지나는 지역의 교통 전체를 재현하는 것이 아니다.** 후자가 필요하면 행정구역 폴리곤이나 사각형 같은 영역 조각을 넓히면 된다 — 그건 애초에 영역 조각의 역할이다.

**전 구간을 살리고 싶은 노선이 있으면 그 노선의 폴리라인을 버퍼를 두른 route_strip 조각으로 추가하면 된다** — §1.1이 이 용도로 둔 조각이다. `v0.1`의 508 특례는 이 판이 낳는 구조 그대로, "508을 그 자신의 route_strip 조각으로 추가한 결과"로 재현된다(§7 예시) — 그 조각은 508 자신의 정류소마다 거리 0이므로 전부 채택되고, 다른 노선의 판정에는 관여하지 않는다.

### 4.1.2 경계 허용치

**정류소 판정에는 scope 경계에서 `STOP_SCOPE_TOLERANCE`(기본 50 m)만큼 여유를 둔다.** 즉 정류소는 "scope 안"이 아니라 "**scope를 `STOP_SCOPE_TOLERANCE`만큼 넓힌 영역 안**"이면 포함이다. §4.1의 순서 판정("벗어나는 첫 정류소부터 제외")도 이 넓힌 영역을 기준으로 한다.

`v0.1`(`SPEC_GenerationScope §1.1`)은 이 문제를 이미 안고 있었다 — 사각형 판정이라 "다리 접속부 정류소는 좌표만으로 완벽히 갈리지 않아 ±1개 오차가 있을 수 있다"고 명시했었다. scope 조각이 사각형뿐이면 이 오차는 예측 가능한 방향(경계선 근처)으로만 생긴다. **행정구역 폴리곤을 쓰면 오차의 성격이 달라진다** — 폴리곤 경계는 도로·다리를 따라가지 않으므로, 다리 위 정류소나 경계 도로변 정류소가 실제로는 그 지역 노선의 일부인데도 폴리곤 바깥으로 좌표가 떨어질 수 있다. 사각형이었으면 안 잘렸을 정류소가 폴리곤에서는 잘리는 경우가 생긴다는 뜻이다.

**도로와 건물에는 이 여유를 적용하지 않는다.** L1/L2는 scope 경계에서 정확히 자른다(§2, §3) — 도로는 애초에 스텁으로 경계를 넘어가고, 건물은 중심점 판정이라 경계 근처 오차가 결과에 크게 영향을 주지 않는다. **정류소만 다르다** — 정류소 위치는 McRIG로 넘어가는 유일한 위치 정보(§7.2)이고, 여기서 하나가 누락되면 노선이 그 지점에서 끊긴 것처럼 보인다. 반대로 scope 밖 정류소를 여유 범위 안에서 하나 더 포함하는 비용은 낮다 — 정류소 하나가 조금 더 생성될 뿐이다. 누락과 과포함의 비용이 비대칭이므로 과포함 쪽으로 기운다.

### 4.2 노선은 선택 입력

노선 데이터가 없으면 M2(`SPEC_Build`)를 건너뛴다. `stops.json`의 `stops`, `routes` 배열은 둘 다 빈 배열로 남는다. 노선 없이 사각형/행정구역 scope만으로 지형·도로·건물을 생성하는 실행이 정상 경로다.

### 4.3 노선/정류소 어댑터

노선·정류소 데이터는 출처마다 형식이 다르다(부산 BIMS, 국가대중교통정보센터, 다른 도시의 등가 기관 등). 이 차이를 흡수하는 파싱 로직을 **소스별 모듈**로 분리하고, 프리셋이 `[transit] adapter = "..."`로 이름을 지정해 고른다 (§5.1).

어댑터가 공통으로 내놓아야 하는 것은 둘뿐이다 — 노선별 정류소 좌표 순서 목록, 그리고 (있다면) 노선 폴리라인. 그 이상의 내부 구조는 어댑터마다 달라도 된다.

## 5. 지역 프리셋 파일

### 5.1 스키마

TOML(권장) 또는 JSON. 필드 구조는 동일하다.

```toml
# preset.toml
name = "yeongdo"

[[scope]]
type = "rect"
lat_min = 35.046
lon_min = 129.028
lat_max = 35.100
lon_max = 129.092

[[scope]]
type = "route_strip"
route = "508"           # transit.adapter가 이 id로 노선을 찾는다
buffer_m = 150

[[scope]]
type = "admin_polygon"
shp_path = "data/행정경계/EMD.shp"
code_field = "EMD_CD"
codes = ["2621010100", "2621010200"]

[transit]                                  # 선택 — 없으면 M2 생략
adapter = "busan_bims"
routes_path = "data/영도구_시내버스_노선현황.csv"
stops_path  = "data/버스_정류소_정보(SHP)"
baseline_date = "2026-xx-xx"

[[bridges]]                                # 선택 — 없으면 다리 없이 생성
name = "영도대교"
format = "도개교"
waypoints = [[e1, n1], [e2, n2]]           # EPSG:5186
moct_node_ids = ["...", "..."]
excluded_link_ids = ["..."]
spec = { span_m = 0, width_m = 0 }

[buildings]                                # 선택 — 없으면 기본 매핑 스키마
dbf_schema = "gis_building_integrated_v1"  # SPEC_Ingest §4 컬럼 매핑 이름

[overrides]                                # 선택 — §6 파라미터 중 원하는 것만
TERRAIN_BUFFER = 1000
```

| 필드 | 내용 | 비고 |
|---|---|---|
| `scope` | §1.1 조각 목록 | 최소 1개 이상 있어야 의미가 있다. 없으면 §5.2 기본값 |
| `bridges` | 교량 목록 | waypoints(EPSG:5186), MOCT 노드 ID, 제외 링크 ID, 형식, 제원. **유일한 진짜 수작업 항목** — 표준노드링크에 교량 형상 필드가 없어 사람이 찾아 넣는다 (`SPEC_Bridge §0`) |
| `transit` | 노선 어댑터 이름 + 데이터 경로 | §4.3 |
| `buildings.dbf_schema` | 건물 dbf 컬럼 매핑 스키마 이름 | `SPEC_Ingest §4` — 배포본마다 컬럼명이 다를 수 있어 매핑 자체를 이름 붙여 분리한다 |
| `overrides` | 파라미터 덮어쓰기 | §6의 아무 값이나, `SPEC_Ingest §2` SCALE 포함 |

### 5.2 프리셋이 없을 때

프리셋은 선택이다. 없으면 다음으로 동작해야 한다.

- scope = CLI로 받은 사각형 하나
- 노선 없음 (`stops.json` 빈 배열)
- 교량 없음
- 건물 dbf 매핑은 기본 스키마
- 파라미터는 전부 §6 기본값

---

## 6. 파라미터

| 이름 | 기본값 | 설명 |
|---|---|---|
| `TERRAIN_BUFFER` | 1000 m | scope 바깥으로 지형을 추가로 까는 폭 (§2) |
| `STUB_LENGTH` | 50 m | L1 분기 도로 잔여 길이 |
| `HIGHRISE_FLOORS` | 15 | L3 원경 건물 최소 층수 |
| `STOP_SCOPE_TOLERANCE` | 50 m | 정류소 포함 판정에만 적용하는 scope 경계 여유 (§4.1.2). 도로·건물에는 적용하지 않는다 |

노선 띠 조각의 버퍼 폭은 전역 파라미터가 아니라 **조각마다 지정하는 값**이다 (§5.1 `buffer_m`) — 노선별로 차창에서 보이는 범위가 다를 이유가 없어 보통 하나의 실행 안에서는 통일해 쓰지만, 구조상 강제되지는 않는다.

모든 거리는 실제 미터로 지정하고, 내부에서 `SCALE`(`SPEC_Ingest §2.2`)을 곱해 블록 거리로 변환한다.

## 7. 영도 프리셋 예시

`v0.1`이 영도·508 전용으로 하드코딩했던 내용을 이 스키마의 구체적인 인스턴스로 옮긴 것이다. 코드가 참조해야 하는 정의가 아니라 **참고용 예시**다.

### 7.1 scope 구성

| 조각 | 내용 |
|---|---|
| 사각형 (또는 향후 행정구역 폴리곤) | 영도구 전역을 감싸는 최소 사각형. 남: 태종대, 북: 부산역·초량, 서: 중앙공원·민주공원, 동: 동삼동. 약 8.0 × 7.1 km, 면적 약 57 km² |
| 노선 띠 | `route = "508"`, `buffer_m = 150` — 부산 버스 508(영도 ↔ 부산역 ↔ 중앙공원·민주공원)의 **전 구간**을 다리 건너까지 포함하려면 이 조각이 필요하다. 조각으로 추가하지 않으면 508도 다른 보조 노선과 똑같이 사각형 경계에서 잘린다 |

**보조 노선(영도 경유 시내버스 20개 + 마을버스 전 노선)은 별도 조각을 받지 않는다.** 이 노선들의 정류소는 §4.1 규칙 그대로 scope(사각형)를 벗어나는 순간 잘린다 — 영도대교·부산대교·남항대교·부산항대교 중 하나를 건너 정류소가 사각형 밖으로 나가면 그 지점부터 제외된다. `v0.1`이 "다리 진입 직전 정류소가 절단 경계"라고 따로 적어뒀던 규칙은 이제 규칙이 아니라 **scope 판정의 자연스러운 결과**다.

### 7.2 노선 데이터

| 용도 | 출처 |
|---|---|
| 영도 경유 시내버스 목록 (20개) | 공공데이터포털 「부산광역시 영도구_시내버스 노선현황」 |
| 영도 마을버스 목록 | 공공데이터포털 「부산광역시 영도구_마을버스 노선현황」 |
| 정류소 좌표·경유 경로 | 부산 BIMS 또는 국가대중교통정보센터 |

**정류소 좌표는 정확해야 한다.** McRIG로 넘어가는 유일한 위치 정보다. **노선 경로는 scope 산출용이므로 대략적이면 된다** — 띠 폭이 150m라 경로가 다소 어긋나도 scope는 거의 같다.

`baseline_date`: 2025년 7월 5일 부산 시내버스 전면개편 이후 여러 차례 보완조정이 있었다. 노선 데이터는 단일 기준일의 스냅샷으로 고정하고, `manifest.json`에 함께 기록한다.

### 7.3 단계 (실행 계획, 스펙 아님)

한 번에 전 범위를 생성하지 않는다. 이 단계 구분은 scope 크기를 실행마다 다르게 잡는 것뿐이다.

| 단계 | scope | 목적 |
|---|---|---|
| **P0** | 영선동 일대 1.5 km 사각형 | 도로 규격·재질·종단선형 검증 |
| **P1** | 영도 전역 (영도대교 이남) | 보조 노선 전 구간, McRIG 주행 시험 |
| **P2** | 부산역·민주공원까지 확장 (508 route_strip 포함) | 508 완전 재현 |

P0에서 파라미터를 확정한 뒤 P1로 넘어간다. P1과 P2는 데이터와 규칙이 동일하므로 프리셋의 scope 조각만 바꾸면 된다.

### 7.4 파라미터

| 이름 | 값 |
|---|---|
| `TERRAIN_BUFFER` | 1000 m |
| `STUB_LENGTH` | 50 m |
| `HIGHRISE_FLOORS` | 15 |
| `STOP_SCOPE_TOLERANCE` | 50 m (기본값 그대로) — 영도대교·부산대교 등 다리 접속부 정류소 판정에서 실제로 쓰인다 |
| 508 노선 띠 `buffer_m` | 150 m |

### 7.5 청크 예산 (참고)

축척 1.75 기준. 실제 노선 폴리라인이 확보되면 재산출한다.

| 조각 | 실면적 (추정) | 청크 (추정) |
|---|---|---|
| 508 노선 띠 (300 m 폭) | 12 km² | 약 144,000 |
| 사각형 + `TERRAIN_BUFFER` | 57 km² | 약 682,000 |

사각형 자체가 영도 전역을 덮으므로, 이 예시에서는 `TERRAIN_BUFFER`가 결과를 크게 바꾸지 않는다 — 노선 띠 하나만 있던 `v0.1` 모델에서 버퍼가 예산을 지배하던 것과 달리, scope에 이미 넓은 사각형이 들어있으면 버퍼의 한계효용이 작다.

## 8. 미정

- 노선 링크 ID와 표준노드링크 링크 ID의 대조 가능 여부
- 508 현재 경로 재확인 — 2025년 개편 반영본 기준
- 마을버스 경유 이면도로가 표준노드링크에 수록되어 있는지 확인 필요. 누락 시 별도 보완
- 행정구역 폴리곤(`admin_polygon`) 실제 데이터 확보 및 코드 필드 확인 — 영도 예시는 아직 사각형으로만 검증됐다
