# SPEC_Build — 구현 순서와 산출물

버전 0.1 · Arnis 포크

---

## 0. 목표 수준

**주행 가능한 도시 맵과, 그 도시 정보의 관리.**

**경계를 명확히 한다.** 노선 설정과 버스 운행은 McRIG 소관이다. 이 생성기는 그 위에서 굴릴 도시를 만들 뿐이다.

| 이 생성기가 하는 일 | McRIG가 하는 일 |
|---|---|
| 도로를 끊김 없이 깐다 | 차량을 주행시킨다 |
| 정류소를 정확한 위치에 둔다 | 노선을 설정하고 정차시킨다 |
| 가로 요소를 배치한다 | 운행 스케줄을 관리한다 |
| 도시 정보를 파일로 남긴다 | 그 파일을 읽어 쓴다 |

따라서 다음 두 가지가 되면 목표 달성이다.

1. 노선이 지나는 도로가 끊김 없이 존재하고, 정류소가 정확한 위치에 있다
2. 도로·건물·정류소 정보가 파일로 남아 조회하고 수정할 수 있다

파사드 디테일, 가로 요소 밀도, 교량 형상은 **이 두 가지가 된 뒤에 올리는 것**이지 먼저 할 일이 아니다.

---

## 1. 최소 완성 조건

M3 단계에서 다음을 만족하면 맵 준비가 성립한다.

| 조건 | 기준 |
|---|---|
| scope 내 도로망 연결성 | scope 안의 도로망이 끊김 없이 연결됨 (`SPEC_Validation §1.2` 노드 해 수렴 실패 성분 수 = 0) |
| 정류소 정확도 | 노선이 있는 실행에 한해 — 전 정류소가 실제 위치에 있고 도로에 접함 |

"교량 연결"은 조건에서 뺐다 — 섬 지역이 아니면 다리 자체가 없을 수 있고, 다리가 있어도 그 다리는 이제 도로망의 일부일 뿐이라 위 연결성 조건에 이미 포함된다. 섬 지역(예: 영도)에서는 다리가 끊기면 애초에 도로망 연결성 자체가 깨지므로 별도 조건으로 둘 필요가 없다.

**정류소 정확도가 유일하게 타협 불가한 항목이다** (노선이 있는 실행에 한해). 정류소가 어긋나면 McRIG 쪽에서 정차 지점을 다시 잡아야 한다.

차량 통과 가능 여부, 회전 반경 적정성 등은 McRIG가 판정할 사항이므로 여기서 검사하지 않는다.

## 2. 실행 품질 단계 (`--quality`)

**M0~M5는 구현 순서이지 실행 옵션이 아니다.** 코드가 어떤 순서로 만들어지는지와, 한 번 실행할 때 무엇을 생성할지는 다른 질문이다. 후자는 `--quality` 옵션으로 따로 정의한다.

| 값 | 포함 |
|---|---|
| `terrain` | 지형 + 도로·인도 |
| `building` | 위 + 건물 매스 |
| `detail` | 위 + 파사드·가로 요소 |

**누적이다.** `building`은 `terrain`의 결과를 전부 포함하고 건물을 더한다.

**도로는 이 옵션에 속하지 않는다.** 어떤 `--quality` 값으로 실행해도 도로는 항상 계획 단계(`SPEC_Ingest §6`)에서 확정한 최고 정합성 그대로 생성된다. `terrain`으로 낮게 뽑아 주행 가능 여부를 먼저 확인하고, 나중에 `detail`로 다시 뽑아도 **도로 형상이 달라지면 안 된다** — 도로가 품질에 따라 달라지면 낮은 품질에서 검증한 주행 가능성이 높은 품질에서 깨질 수 있다. 같은 이유로 `SPEC_RoadProfile P5`의 평활화 반복 횟수도 품질 단계에 연동하지 않는다.

계획은 품질과 무관하게 항상 전부 계산한다. `--quality`가 결정하는 것은 그 계획 중 무엇을 실제로 블록으로 옮기느냐뿐이다 (`SPEC_Ingest §6` 생성 단계).

## 3. 구현 단계

### M0. 좌표와 지형

- 포크 저장소 준비, 입력 소스 옵션 구조
- 좌표계 변환 (`SPEC_Ingest §2`)
- 지형 생성 — Arnis 내장 고도 사용, 입력부는 교체 가능하게 분리 (`SPEC_Ingest §5`)

**완료 기준** — 영선동 1.5 km 사각형의 지형이 실제 등고와 대체로 맞는다. 렌더 이미지로 봉래산 사면이 확인된다. 30 m급 해상도이므로 세부 경사는 기대하지 않는다.

### M1. 도로

- 표준노드링크 적재, 등급 매핑 (`SPEC_Ingest §3`)
- 종단선형 (`SPEC_RoadProfile` P3 이후)
- 단면 스윕, 연석, 인도 (`SPEC_RoadSection`)
- `roadgraph.json` 출력

**완료 기준** — 경사 제약 위반 0건. 교차로 높이 일치. 렌더 이미지로 도로가 매끄럽다.

**도색·횡단보도는 이 단계에서 하지 않는다.** 주행에 영향이 없다.

### M2. 범위와 노선 — **선택 단계**

노선 데이터가 있는 실행에서만 수행한다. 없으면 이 단계를 건너뛰고 `stops.json`은 빈 배열로 남긴다 (`SPEC_Scope §4.2`).

- 노선 폴리라인 구성, scope 조각으로 반영 (`SPEC_Scope §1.1` 노선 띠)
- 정류소 좌표 배치, scope 판정으로 포함/제외 (`SPEC_Scope §4.1`)
- `stops.json` 출력

**완료 기준** — 전 정류소가 실제 위치에 배치되고 도로에 접한다. 노선 폴리라인은 scope 산출용이므로 대략적 정확도로 충분하다.

### M3. 교량과 완주

- 영도대교·부산대교 상판 및 접속부 (`SPEC_Bridge §6.1, §6.2`)
- 남항·부산항대교는 램프 절단면만
- **§1 완주 조건 자동 검사**

**완료 기준** — §1 최소 완성 조건 2개 통과. 여기서 McRIG에 인계.

**아치·주탑·케이블은 이 단계에서 하지 않는다.** 상판만 있으면 달릴 수 있다.

### M4. 건물

- 건물통합정보 적재, 유형 결정 (`SPEC_BuildingType §3`)
- 외곽선 래스터화, 도로 침범 오려내기
- 경사지 처리 (`SPEC_BuildingType §10`)
- 파사드, 옥상
- L3 원경 고층
- `buildings.json` 출력

**완료 기준** — 건물이 지형에 뜨거나 묻히지 않는다. 도로를 막지 않는다.

### M5. 마감

우선순위 순으로, 되는 만큼만.

1. 전주·전선 (`SPEC_StreetFurniture §2`)
2. 버스정류장 승차대 (§3)
3. 도로 도색·횡단보도 (`SPEC_RoadSection §3`)
4. 가로등 (§4)
5. 교량 아치·주탑 (`SPEC_Bridge §6.2, §6.3`)
6. 가로수, 신호등, 기타 (§5, §6, §7)

**여기부터는 언제 멈춰도 된다.** M3까지가 목표이고 M5는 덤이다.

## 4. 산출 데이터

월드 폴더와 나란히 둔다. 월드 안에 표지판이나 데이터 블록으로 심지 않는다.

```
world/
manifest.json
roadgraph.json
stops.json
buildings.json
validation_report.json
```

`roadgraph.json`/`buildings.json`/`stops.json`은 `SPEC_Ingest §6` 계획 단계에서, `validation_report.json`(`SPEC_Validation §4`)은 기록 단계에서 나온다.

### 4.1 `manifest.json`

생성 조건의 기록. 이것이 없으면 나중에 무엇으로 만든 맵인지 알 수 없다.

```json
{
  "generated_at": "...",
  "scale": 1.75,
  "origin": { "epsg": 5186, "e0": 0, "n0": 0, "h0": 0, "y2_base": -88 },
  "elevation_mapping": { "h_linear": 120, "compression": 0.0, "max_source_elevation": 0.0 },
  "bbox": [x_min, z_min, x_max, z_max],
  "sources": [
    { "name": "표준노드링크", "version": "...", "retrieved": "..." },
    { "name": "건물통합정보", "version": "...", "retrieved": "..." },
    { "name": "고도데이터", "source": "arnis-builtin", "version": "...", "retrieved": "..." },
    { "name": "버스노선", "baseline_date": "...", "retrieved": "..." }
  ],
  "parameters": { }
}
```

**`origin`이 핵심이다.** 이 값이 있으면 언제든 블록 좌표와 실제 좌표를 오갈 수 있다. 앞서 좌표 복원에 애를 먹은 이유가 이 기록이 없어서였다.

**`sources`의 기준일도 필수다.** 버스 노선은 2025년 개편 이후 여러 차례 바뀌었으므로, 어느 시점 기준인지가 기록되지 않으면 재현이 불가능하다.

### 4.2 `roadgraph.json`

`SPEC_RoadProfile §2.3` 형식. 여기에 다음을 추가한다.

| 항목 | 내용 |
|---|---|
| `link_id` | 표준노드링크 원본 ID |
| `lanes` | 차로수 |
| `road_class` | A~F 단면 등급 |
| `oneway` | 일방통행 여부 |
| `is_bridge` | 교량 구간 여부 |

### 4.3 `stops.json`

```json
{
  "stops": [
    {
      "stop_id": "...",
      "name": "...",
      "pos": [x, z],
      "y2": 0,
      "routes": ["508", "..."],
      "shelter": true
    }
  ],
  "routes": [
    { "route_id": "508", "type": "시내", "links": ["..."], "stops": ["..."] }
  ]
}
```

McRIG 주행 시나리오가 이 파일을 그대로 읽을 수 있어야 한다.

### 4.4 `buildings.json`

```json
{
  "buildings": [
    {
      "building_id": "...",
      "footprint": [[x, z], "..."],
      "floors": 0,
      "type_code": "R-e2",
      "ground_y2": 0,
      "front_segment": "s0031",
      "detail_level": "L2",
      "clipped": false,
      "omitted": false
    }
  ]
}
```

**`omitted`가 필요한 이유** — 도로 침범으로 생략된 건물도 기록해야 나중에 왜 비어 있는지 알 수 있다.

이 파일이 `SPEC_BuildingType §9` 로드뷰 덮어쓰기의 대상 목록이 된다.

## 5. 재실행 원칙

- 원본 데이터와 파라미터가 같으면 결과가 같다 (결정론)
- 산출 데이터만 있으면 어느 단계부터든 다시 시작할 수 있다
- 월드는 매번 새로 쓰고, 손으로 지은 것은 월드 안에 두지 않는다

**손으로 지은 건축물은 스키매틱으로 따로 보관한다.** 월드에 두면 재생성 때마다 사라진다.

## 6. 지금 하지 않는 것

- 로드뷰 태깅 — `buildings.json`이 나온 뒤, 필요한 만큼만
- 건물 간 중첩 처리
- 계단길, 아파트 단지 부속
- 램프·나들목 정밀 형상
- 실내 인테리어
- 신호 체계, 교통 시뮬레이션

이 목록은 버리는 것이 아니라 **M3 이후로 미루는 것**이다.
