# SPEC_Validation — 검증 지표와 경고 문턱

버전 0.1 · Arnis 포크

---

## 0. 원칙

**게임에 진입하지 않고 판단할 수 있어야 한다.**

`SPEC_Ingest §6`의 계획 단계는 블록을 한 개도 쓰지 않고 scope 전체를 한 번 훑어 도로 높이·건물 지반고·유형·충돌을 전부 확정한다. 이 지표들은 바로 그 계획 단계의 산출물이다 — 월드를 열어보지 않아도 이 실행이 정상인지, 다른 지역에서 무언가 어긋났는지 숫자로 먼저 알 수 있어야 한다.

특히 이 문서는 **일반화의 안전망**이다. `SPEC_Ingest §4`의 dbf 컬럼 매핑처럼 지역마다 조용히 어긋날 수 있는 가정이 실제로 어긋났을 때, 속성 공백 비율과 유형 분포가 가장 먼저 튄다. 매 실행 후 자동으로 찍히지 않으면 그 어긋남은 완성된 월드를 직접 돌아보기 전까지 드러나지 않는다.

---

## 1. 계획 단계 산출 지표

모두 `SPEC_Ingest §6` 계획 단계에서, 블록 배치 없이 산출한다.

### 1.1 건물

| 지표 | 내용 |
|---|---|
| 로드 수 | 입력 shp에서 읽은 건물 개수 |
| 배치 수 | 실제로 생성 대상이 된 건물 개수 (`SPEC_RoadSection §5` 침범 처리 후) |
| 제외 수 / 제외 비율 | 도로 침범으로 생략된 건물 수와 그 비율 |
| 속성 공백 비율 | 층수·용도·사용승인일 **각각** 따로. 하나로 뭉치면 어느 필드가 문제인지 안 보인다 |
| 유형 분포 | `SPEC_BuildingType §3` 유형 코드(`R-e2` 등)별 건물 수 |
| 경사지 단 나눔 건물 수 | `SPEC_BuildingType §10.2`에서 `Δ ≥ 7`로 판정된 건물 수 |

### 1.2 도로

| 지표 | 내용 |
|---|---|
| 총 연장 | scope 내 도로 총 길이 |
| 종단 경사 히스토그램 | `SPEC_RoadProfile` 구간별 경사 분포 |
| 구조물 수 | 교량·터널 구간 개수 |
| 경사 제약 위반 잔존 건수 | `SPEC_RoadProfile P5` 정수화 후에도 `MAX_SLOPE`를 넘는 구간 수 (0이 정상) |
| 옹벽 생성량 | `SPEC_RoadProfile P8` 옹벽으로 처리된 지점 수 |
| 노드 해 수렴 실패 연결 성분 수 | `SPEC_RoadProfile P4`가 `MAX_ITER` 내 수렴하지 못해 원본 유지로 빠진 연결 성분 수 (0이 정상) |

### 1.3 범위

| 지표 | 내용 |
|---|---|
| scope 면적 | `SPEC_Scope §1` 합집합 면적 |
| 생성 대상 타일 수 | L0 기준 |
| 노선·정류소 포함 수 | 노선이 있는 실행에 한해 — 노선별 포함/제외 정류소 수 |

## 2. 경고 문턱

값을 찍는 것만으로는 부족하다 — 무엇이 정상 범위를 벗어난 것인지 미리 정해두지 않으면 매번 사람이 판단해야 한다.

| 지표 | 경고 문턱 | 근거 |
|---|---|---|
| 건물 속성 공백 비율 (필드별) | 20% 초과 | 영도 실측 기준 결측은 소수다. 갑자기 늘면 `SPEC_Ingest §4` dbf 컬럼 매핑이 그 지역 배포본과 어긋났다는 첫 신호 |
| 건물 유형 분포 | 단일 유형이 80% 초과를 차지 | 실제 도시는 용도가 섞인다. 한 유형에 쏠리면 매핑이 깨져 대부분이 결측 기본값(`SPEC_BuildingType §1` 결측 처리)으로 떨어지고 있다는 뜻일 가능성이 높다 |
| 건물 제외 비율 | 15% 초과 | `SPEC_RoadSection §5` 침범 기준상 정상 범위를 넘는 수치. 도로·건물 데이터 정합이 그 지역에서 크게 어긋났을 수 있다 |
| 경사 제약 위반 잔존 건수 | 0 초과 | 정의상 0이어야 한다. 하나라도 있으면 `SPEC_RoadProfile P5` 재분배가 실패한 구간이 있다는 뜻 |
| 노드 해 수렴 실패 연결 성분 수 | 0 초과 | 동일. 해당 성분은 원본 지형 그대로 남아 매끄럽지 않다 |
| 옹벽 생성량 | scope 도로 총 연장의 5% 초과 | 과도하면 `RETAINING_THRESHOLD`가 그 지역 지형에 안 맞을 수 있다 (완만한 지형에 옹벽이 남발되거나, 급경사 지역에서 임계값이 너무 높거나) |

경고는 생성을 막지 않는다 — 기록하고 넘어간다. 예외는 `SPEC_Ingest §4`의 자기 검증(날짜 형식·용도 코드집합 대조)뿐이다. 그것은 경고가 아니라 **중단**이다 — 컬럼 매핑 자체가 잘못됐다면 이후 모든 지표가 의미 없어진다.

## 3. 구조 무결성 검사

통계 지표와 달리 통과/실패만 있는 검사. `SPEC_RoadProfile §6`이 정의했던 자동 검사를 이 문서로 흡수한 것이다.

| 검사 | 내용 |
|---|---|
| 경사 제약 | 도로 마스크 전 지점에서 인접 `y2` 차이가 `MAX_SLOPE`(`SPEC_RoadProfile §4`) 이하인가 |
| 노드 높이 일치 | 각 노드에 모이는 구간 끝점 높이가 모두 동일한가 |
| 뜬 구조 지지 | `ELEVATED` 구간 하부에 지지 구조(교각 등)가 실제로 연결되어 있는가 |
| 터널 통행고 | `TUNNEL` 구간 내부 통행 높이가 `TUNNEL_CLEARANCE` 이상 확보되는가 |

`SPEC_Ingest §6` 계획 단계가 도로 종단선형을 전부 실수로 확정한 뒤 정수화하므로, 이 네 검사는 **블록을 쓰기 전, 계획 결과만으로** 판정할 수 있다. `SPEC_RoadProfile §6`이 처음부터 "게임에 진입하지 않고 확인한다"는 원칙이었던 것과 같은 이유다 — 다만 이제는 도로 재작성 후처리가 아니라 계획 단계 자체의 산출물이라 별도로 월드를 다시 열 필요가 없다.

## 4. 산출 형식

매 실행 후 `validation_report.json`으로 `world/` 폴더와 나란히 남긴다. `SPEC_Build §3` 산출물 목록에 추가된다.

```json
{
  "generated_at": "...",
  "buildings": {
    "loaded": 0, "placed": 0, "omitted": 0, "omitted_ratio": 0.0,
    "attribute_gaps": { "floors": 0.0, "use": 0.0, "approval_date": 0.0 },
    "type_distribution": { "R-e2": 0, "...": 0 },
    "terraced_slope_count": 0
  },
  "roads": {
    "total_length_m": 0,
    "slope_histogram": [],
    "structures": { "bridges": 0, "tunnels": 0 },
    "slope_violations_remaining": 0,
    "retaining_walls": 0,
    "unconverged_components": 0
  },
  "scope": {
    "area_km2": 0.0,
    "tiles": 0,
    "routes": [ { "route_id": "...", "stops_included": 0, "stops_excluded": 0 } ]
  },
  "warnings": [ { "metric": "...", "value": 0.0, "threshold": 0.0 } ]
}
```

규칙(문턱값, 매핑 스키마 등)을 바꾼 뒤 이 파일을 이전 실행분과 비교하면, 렌더 이미지를 다시 뽑지 않고도 변경이 지표를 어느 방향으로 움직였는지 확인할 수 있다.
